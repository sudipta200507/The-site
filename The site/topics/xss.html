Cross-Site Scripting (XSS)

Cross-Site Scripting (XSS) allows attackers to inject malicious scripts into web pages viewed by other users. It exploits the trust users have in a website's content.

7 min read Updated: July 2026

What is Cross-Site Scripting?

XSS occurs when an application includes untrusted data in a web page without proper validation or escaping. The malicious script then executes in the victim's browser.

Analogy: Imagine a company's internal newsletter that prints employees' submitted comments. If someone submits a comment with a hidden microphone script, every reader would unknowingly start recording audio.

XSS Attack Flow

Vulnerable Code Example

VULNERABLE
// JavaScript - Rendering user input directly
app.get('/profile', (req, res) =>
  const name = req.query.name;
  res.send(`
    <h1>Hi ${name}</h1>
  `);
});

Problem: The name parameter is inserted directly into HTML without escaping.

SAFE (FIXED)
// Using proper escaping
const escapedName = name
  .replace(/&/g, '&amp;')
  .replace(/</g, '&lt;')
  .replace(/"/g, '&quot;');
res.send(`Hi ${escapedName}`);

Fix: Escape HTML special characters before rendering.

Why This Matters for Pentesting

XSS is one of the most common vulnerabilities because it allows attackers to steal session tokens, keylog, deface pages, or redirect to malicious sites.

XSS Attack Examples

<script>alert('XSS');</script>
<img src="x" onerror="alert('XSS')">
<svg onload="alert('XSS')">

Prevention

  • Output Encoding: Always encode data before rendering
  • Content Security Policy (CSP): Use CSP headers
  • Input Validation: Validate and sanitize all user input
  • Use Modern Frameworks: React, Vue, Angular have built-in protection
