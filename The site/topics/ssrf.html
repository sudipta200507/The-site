Server-Side Request Forgery (SSRF)

SSRF tricks a server into making unintended requests to internal or external systems.

6 min read

What is SSRF?

Server-Side Request Forgery occurs when an application fetches a URL supplied by the user without validation. The attacker can use this to probe internal services or access cloud metadata.

Analogy: A library service that fetches books from other libraries. If you can tell it "fetch from this library's internal system," you could access employee records.

SSRF Attack Flow

Why This Matters for Pentesting

SSRF can lead to cloud metadata access, internal network scanning, and port scanning. It's often a stepping stone to credential theft.

SSRF Attack Examples

# Cloud metadata services
http://169.254.169.254/
# Internal services
http://127.0.0.1:8080/
http://10.0.0.1/internal-api

Prevention

  • URL Validation: Allow only http/https, validate URL format
  • IP Blacklist: Block private and loopback IPs
  • DNS Rebinding Protection: Resolve and validate before connecting
  • Whitelist Domains: Only allow specific approved domains
