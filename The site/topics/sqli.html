SQL Injection (SQLi)

SQL Injection is a code injection technique that allows attackers to interfere with the queries that an application makes to its database. It remains one of the most dangerous and common web application vulnerabilities.

8 min read Updated: July 2026

What is SQL Injection?

SQL Injection (SQLi) occurs when user input is directly concatenated into SQL queries without proper sanitization or parameterization. This allows attackers to modify the query structure and execute arbitrary SQL commands.

Analogy: Think of a SQL query as a recipe with placeholders for ingredients. If you don't properly secure the ingredient slots, someone could slip in poison or a different recipe entirely - and the cook (database) would have no way to tell the difference.

How SQLi Works

Vulnerable Code Example

VULNERABLE
// Python/Flask example
def get_user(username):
  query = "SELECT * FROM users WHERE username = '" + username + "'"
  cursor.execute(query)
  return cursor.fetchall()

Problem: The username parameter is directly concatenated into the SQL string.

SAFE (FIXED)
// Using parameterized queries
def get_user(username):
  cursor.execute("SELECT * FROM users WHERE username = ?", (username,))
  return cursor.fetchall()

Fix: Use parameterized/prepared statements.

Why This Matters for Pentesting

SQL Injection is consistently ranked as the #1 most dangerous web application vulnerability because it can lead to data exfiltration, data manipulation, and authentication bypass.

Common SQLi Attack Patterns

# Union-based attack
' UNION SELECT username, password FROM users --
# Boolean-based blind
' AND (SELECT SUBSTRING(password,1,1) FROM users WHERE id=1) = 'a' --
# Time-based blind
' AND (SELECT CASE WHEN (1=1) THEN WAITFOR DELAY '0:0:5' ELSE '' END) --

Testing for SQL Injection

# Basic test
'
# OR injection
' OR '1'='1
# Comment injection
' OR 1=1 --

Prevention Best Practices

  • Parameterized Queries: Always use prepared statements with placeholders
  • Input Validation: Whitelist expected input patterns
  • Least Privilege: Database user should have minimal necessary permissions
